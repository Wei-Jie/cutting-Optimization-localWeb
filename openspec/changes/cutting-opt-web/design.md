## Context

2011 年的二維切割最佳化演算法（王韋傑碩士論文）面臨效能瓶頸（產品組合 > 5 組時運算緩慢）且缺乏現代 Web 展示介面。使用者希望將其 Web 化，並具備穩定且防止系統崩潰的排程運算機制。

## Goals / Non-Goals

**Goals:**

- 重現並優化論文中的二維切割演算法（Non-guillotine）。
- 實作「最大空矩形 (MER)」分割邏輯以避開指定座標的矩形瑕疵。
- 建立一個穩定的 Web 服務（FastAPI），支援任務排程（防止並發計算導致當機）。
- 提供互動式 Web 介面，讓使用者可以設定參數、標記瑕疵並觀看切割圖。

**Non-Goals:**

- 本階段不考慮支援不規則形狀（僅限矩形產品與瑕疵）。
- 不實作使用者帳號管理與持久化歷史記錄（僅限單次會話運算）。
- 不考慮分散式 Worker（僅限單機背景任務隊列）。

## Decisions

- **後端技術選型 (FastAPI + BackgroundTasks)**：
  - 理由：FastAPI 輕量且內建支援非同步任務。使用 `BackgroundTasks` 結合一個單執行緒的背景 Queue，可以輕鬆限制併發運算數，防止 CPU 耗盡導致 Web Server 崩潰。
- **演算法優化 (Pruning + Memoization)**：
  - 理由：針對遞迴爆炸問題，我們將使用 `lru_cache` 記錄「剩餘面積 + 剩餘清單」的狀態，並在當前利用率無法超越已知最佳解時提前剪枝。
- **空間分割 (MER Algorithm)**：
  - 理由：使用最大空矩形算法可以確保在不規則的剩餘空間中找到最優放置點。
- **前端渲染 (HTML5 Canvas)**：
  - 理由：在網頁端直接繪圖，反應速度快，不需要頻繁請求圖片檔案，且方便實作互動式瑕疵標記。

## Risks / Trade-offs

- **風險：記憶體占用**：過深或過廣的遞迴搜尋即使有優化，也可能占用大量記憶體。
  - **對策**：設定最大递归深度與最大搜尋時間限制。
- **權衡：單執行緒 Worker**：限制單一 Worker 會導致多使用者時需要排隊等待。
  - **對策**：這正是使用者要求的「防止崩潰」機制，優先保證系統穩定性。
